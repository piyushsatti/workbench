# Agent files

Agent files are derived routing surfaces. Canonical behavior lives in focused standards in this rulebook set.

## Allowed shape

- A minimal global file is optional. If present, it contains only indispensable universal behavior.
- The global file contains no identity, task routing, or standards catalog.
- Executable project or independently owned repository roots may have entrypoints that route roles to the few canonical standards they need.
- Do not create organizational workspace, category, or arbitrary nested-folder instruction layers.
- An entrypoint may repeat an indispensable brief derived summary. Lineage stays documented in canonical standards. Project entrypoints may link their canonical sources; the minimal global does not require routing pointers. No derivative may become an independent or competing rule source.
- Harness-global shims point only to the minimal global file. Harness residue belongs in its owning role or canonical standard.
- A human-authored instruction for the current task overrides an older derived file. Resolve durable conflict by changing the canonical source first.
- Do not use symlinks for agent-file wiring.

## Maintenance

- Add durable behavior after repeated evidence or explicit human instruction.
- Prune rules that no longer apply; retain evidence in history rather than always-loaded text.
- Keep bullets short and route detail to one canonical reference.
- Mechanically check for secrets, broken pointers, duplicate rules, symlink wiring, and unowned text.
- Date changes. Do not invent semantic-version requirements or bumps.

Harness-required entity-root shims are legitimate adapters when they point to the owning entrypoint or permitted minimal global and contain no competing rules.
