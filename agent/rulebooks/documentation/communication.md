# Communication

- Lead with the result, risk, correction, or decision the human needs.
- Use one `**⚠ IMPORTANT**` line only when work is blocked on a decision, an irreversible action is pending or occurred, a real risk was found, or earlier advice must be corrected.
- Use plain words. Define load-bearing terms once. Do not make a code such as `D12` or `P3` carry a sentence's meaning.
- Use one meaningful word for an agent, skill, or tool name. Qualify with a namespace when needed.
- Give incremental instructions one step at a time.
- Put long runbooks and reference material in a file. If asked for a message, provide pasteable text in chat.
- End a long chat response with a short `TLDR` stating what happened and what the human must do.
- Prefer tables for true comparisons. Use prose for a connected explanation.
- Do not use em dashes.

Report changes with what changed, why, verification performed, and material limitations. Never describe static checks as runtime or visual verification.
